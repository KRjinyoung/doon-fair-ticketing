# AI 매크로 탐지 실험 결과 (2026-10-15)

격리 실험판에서 사람 시뮬레이터와 실제 봇으로 38회차를 돌려 얻은 결과다.
설계는 [08-ai-macro-plan.html](08-ai-macro-plan.html)을 따랐다. 코드는 `feat/bot-rules` 브랜치에 있다.

## 한 줄 결론

> **"5번 연속, 오픈 후 도착 시각이 12ms 안에서 똑같으면 매크로."**
> 서울 AI가 이 규칙을 스스로 찾았다. 회차가 끝날 때마다 다시 배우고, 사람이 걸리지 않는지 스스로 검사한 뒤
> 0.2초 만에 전국 PoP에 반영한다. 처음 보는 매크로도 5번째 관찰 뒤 다음 회차부터 막혔고, 사람은 360건 중 0건 막혔다.

반응 속도 자체는 판단에 쓰지 않는다. 카운트다운이 있으면 사람도 0초에 맞춰 누르기 때문이다(08 §9 결정).
보는 것은 **"여러 번에 걸쳐 기계처럼 똑같은가"** 하나다.

- 봇: 같은 코드가 매번 같은 순간에 쏜다. 5회 흩어짐 0.2~8.6ms.
- 사람: 기기 시계, 손, 망설임이 매번 다르다. 5회 흩어짐 최소 16.6ms, 중앙 708ms.
- 1·2차(PoP·중앙)는 요청 하나를 그 자리에서 본다. 이 차이는 회차를 쌓아 보는 3차(서울)에서만 보인다.

## 1. 실험 환경

| 구성 | 내용 |
|---|---|
| 격리 실험판 (`sim/`) | 판교 안에 라이브와 분리해 띄운 복사본. PoP 2개(판교·대전 이름), central, Kafka, Redis, Postgres. 외부 접속 불가, 서울로도 안 감 |
| 서울 AI 역할 | 실험판 안의 컨테이너 `doonsim-seoul`에서 `seoul/auto_rules.py` 실행 (라이브에서는 서울 치타에서 같은 코드) |
| 회차 | `seat.html?every=1`처럼 1분 배수 정각에 오픈, 30초 열림. `bots/rounds.py`가 사람과 봇을 같은 오픈 시각에 출발시키고 정답표(`rounds.jsonl`)를 남긴다 |
| 사람 | `sim/humans.py` 가상 사람 40명 (계정 user01~40, 판교·대전 절반씩). 아래 2절 |
| 봇 3종 | 단순(파이썬 UA, v0에 걸림) / 위장(크롬 UA·한국어, Referer 없음) / 스텔스(진짜 크롬 + stealth 플러그인, 헤더가 진짜 브라우저와 같음). 회차마다 종류별 3개 |

## 2. 사람 시뮬레이터

참가자를 모집할 수 없어 사람은 시뮬레이터로 만들었다(08 결정). 수치는 파일 맨 위 `P` 한 곳에 모아 두었다.

| 항목 | 값 | 근거 |
|---|---|---|
| 기기·브라우저 | 안드로이드 크롬 30%, 아이폰 사파리 30%, PC 크롬 20%, 삼성 인터넷 10%, 아이패드·파이어폭스 등 | 한국 이용 비율에 맞춤 |
| 헤더 순서·값 | 실제 기기 로그(아이폰 사파리, 파이어폭스)와 진짜 크롬(HTTP)에서 그대로 복사 | 사람 40명 중 4명은 스텔스 봇과 헤더가 **완전히 같다** |
| 기기 시계 오차 | 사람마다 고정, 표준편차 120ms | 폰 NTP 오차 수준 |
| 반응형 (75%) | 반응 시간 로그정규, 중앙 0.45초 | Woods 2015 단순 반응 ~0.25초 + 버튼까지 이동 |
| 미리 연타형 (25%) | 0초 직전부터 연타, 잠금이 풀린 뒤 첫 클릭만 나감 | Repp 2005 (예측 가능한 신호에 미리 맞춰 침) |
| 그 밖 | 참여 85%, 좌석 미리 고름 70%, 지면 다른 좌석으로 최대 3번 | |

봇과 사람의 **헤더로는 구별이 안 되게** 만드는 것이 목표였다. 실험 중 가짜 차이 두 개를 찾아 없앴다.
- 실험판 주소가 `localhost`였을 때 크롬이 라이브(HTTP)에서는 안 보내는 `sec-fetch-*`, `sec-ch-ua`를 붙였다 → 주소를 사설 IP로 바꿨다.
- 스텔스 봇이 `Accept-Language: en-US`였다 → 한국 매크로처럼 `ko-KR`로 바꿨다.

## 3. 결과 ① v0(기존 규칙)의 한계 — 1~20회차, 1차 필터 monitor

| | 좌석 요청 | v0가 잡음 |
|---|---|---|
| 단순 봇 | 60 | **60 (100%)** |
| 위장 봇 | 60 | 0 |
| 스텔스 봇 | 60 | 0 |
| 사람 (판교 347 / 대전 361) | 708 | 0 |

기존 규칙은 User-Agent가 이상한 봇만 잡는다. 위장·스텔스 봇은 하나도 못 잡는다. AI가 메울 빈틈이다.

## 4. 결과 ② 시간 분포 — 계정별 '연속 5회 도착 흩어짐'

38회차 전체, v0를 통과한 좌석 요청만, 연속 5회 창마다 '오픈 후 첫 도착 시각'의 표준편차.

| | 최소 | 중앙 | 최대 | 창 수 |
|---|---|---|---|---|
| 위장 봇 | 0.2ms | 0.7ms | 1.3ms | 23 |
| 스텔스 봇 | 4.2ms | 5.1ms | 8.6ms | 23 |
| 사람 | **16.6ms** | 708ms | 2,771ms | 1,115 |

AI(그래디언트 부스팅 + 깊이 3 결정나무)가 찾은 선: **연속 5회 흩어짐 ≤ 12.6ms** (봇 최대와 사람 최소 사이).

| 지표 (계정 단위 5겹 교차 검증, 처음 보는 계정) | 결과 |
|---|---|
| 봇 계정 탐지 | 26/26 (100%) |
| 사람 오탐 (어느 5회 창이라도 걸리면 오탐으로 셈, 엄격) | 1/40 |
| 짧은 규칙과 큰 모델의 답이 같은 비율 (충실도) | 98% |

## 5. 결과 ③ 자동 반영 시연 — 29~38회차, 1차 필터 enforce (시연 녹화 대상)

AI가 **한 번도 본 적 없는 새 봇 계정 9개**(bot40~48)만 썼다. 정답은 1~20회차 것만 학습에 쓰고,
21회차 이후 봇 정답은 쓰지 않았다. 새 봇은 오직 시간 분포만으로 잡혀야 한다.

| 회차 | 봇 성공 | 서울 AI | 사람 막힘 |
|---|---|---|---|
| 29~33 | 6/9 (단순 3개는 v0가 막음) | 새 봇은 관찰 5회 미만이라 판단 보류 | 0 |
| 33회차 뒤 | — | 재학습 → 자동 검사 통과(사람 0명) → **v1 전국 배포 0.2초**, 새 계정 6개 추가 | — |
| 34~38 | **0/9** | 매 회차 재학습, 변화 없음 | 0 |

PoP 로그 기준 합계: 위장·스텔스 봇 요청 30건 중 처음 15건 통과 → 이후 15건 전부 AI 규칙으로 차단.
단순 봇 30건 전부 v0 차단. **사람 360건 전부 통과 (대전 176 / 판교 184, 지역별 차단율 모두 0%).**

자동 반영 흐름 (사람 승인 대신 자동 검사, 사람은 비상 정지만):

```
회차 종료 → 서울 AI 재학습(0.1~0.2초) → 자동 검사: 알려진 사람의 어느 5회 창도 안 걸리나?
   → 통과: bot-rules 토픽 발행 → 전국 PoP 1초 안에 교체 → 다음 회차부터 차단
   → 실패: 배포 보류, 이전 규칙 유지
비상 정지 = 빈 규칙 묶음 발행 → 즉시 v0로 복귀
```

## 6. 일부러 어렵게 — 어디서 깨지나 (`sim/stress.py`)

실험판 회차는 하나에 2분이라, 같은 사람 행동 코드(`Human.first_click`)로 HTTP 없이 시각만 뽑아 수천 회차를 흉내 냈다.

**사람을 점점 기계처럼** (400명 × 16회차, 어느 5회 창이라도 걸린 사람)

| 사람 유형 | 걸린 비율 |
|---|---|
| 기본 (실험판과 같음) | 0.2% |
| 모두 좌석을 미리 골라 둠 | 0.5% |
| + 반응 시간 흔들림 절반 | 1.8% |
| 티켓팅 고수: 미리 골라 두고 0초에 연타 | 1.2% |
| 고수 + 아주 빠른 연타 (80~120ms 간격) | **25.2%** |

**봇이 매 회차 0~J ms 무작위 지연을 섞으면** (학습 때 본 적 없는 봇)

| J | 탐지 | 봇 도착 중앙 | 봇보다 늦게 도착하는 사람 |
|---|---|---|---|
| 0~20ms | 100% | 33~42ms | 96% |
| 30ms | 96% | 47ms | 95% |
| 50ms | 45% | 58ms | 95% |
| 100ms | 5% | 81ms | 94% |
| 200ms | 0% | 131ms | 90% |

해석:
- 정각에 그대로 쏘는 **일반 매크로는 오탐 0.2% 수준으로 확실히 잡는다.**
- **지연을 50ms 이상 섞는 고급 봇은 시간만으로는 못 잡는다.** 그래도 사람 95%보다 빠르다. "AI를 피하려면 느려져야 한다"는 주장은 성립하지 않는다.
  → 실제 운영에서는 계정·기기 신호(한 기기 다계정, 갓 만든 계정)를 함께 본다. 실험판에서 이 신호를 넣으면 '같은 기기 계정 수 > 5.5'로 봇을 모두 잡았다. 다만 이 값은 시연용으로 심어 둔 것이라 이번 시연 범위에서는 뺐다.
- 아주 빠르게 연타하는 고수는 오탐이 커진다. 그래서 차단 대신 추가 인증(캡차)이나 결제 보류로 처분하는 것이 맞다.

## 7. 실험 중 고친 것 (다시 하지 않도록)

| 문제 | 원인 | 고친 것 |
|---|---|---|
| 첫 규칙 '흩어짐 ≤ 199ms'가 새 사람을 3회 관찰로 보면 35% 잡음 | 사람을 12회차 이상 긴 기록으로만 학습·검사함 (긴 기록은 늦은 회차가 끼어 흩어짐이 커짐) | 학습과 자동 검사를 '연속 N회 창' 단위로 |
| 3회 창에서도 사람·봇이 겹침 (자동 검사가 실제로 배포를 막음) | 3번이면 우연히 비슷한 사람이 나옴 (사람 창 1만 개 중 29개 겹침) | **5회 창** (겹침 0개, 여유 4.7ms) |
| 짧은 규칙의 선이 29.4ms로 사람 쪽에 밀림 | 짧은 규칙이 큰 모델의 답을 흉내 냈는데, 큰 모델이 7~29ms를 한 칸으로 묶음 | 짧은 규칙은 정답으로 직접 배우고, 큰 모델은 충실도 측정용 |
| 회차마다 규칙 버전이 들락날락 (경계 계정 하나) | 매 회차 새 데이터로 선이 조금씩 움직임 | 한 번 걸린 계정은 계속 차단 |

## 8. 한계 (발표에서 밝힐 것)

1. **사람은 시뮬레이션이다.** 수치는 문헌 값이고, 헤더는 실기기에서 따왔다. 봇은 진짜 크롬·스텔스 플러그인이다. 통제된 실험의 상한으로 읽어야 한다.
2. **새 매크로는 5번까지 통과한다.** 5번 관찰해야 판단한다.
3. **지연을 섞는 고급 봇은 시간 분포만으로는 못 잡는다** (6절).
4. 실험판 기준이다. 라이브 PoP·진짜 서울에는 아직 배포하지 않았다. 시연은 실험판 녹화본으로 한다.

## 9. 예상 질문

- **"결국 if문 아닌가요?"** → 선(12.6ms)을 사람이 정하지 않았습니다. AI가 기록에서 찾았고, 회차마다 다시 찾습니다. 큰 모델과 짧은 규칙이 98% 같은 답을 내는 것도 확인했습니다. 실시간 경로에는 설명 가능한 짧은 규칙만 내려보냅니다.
- **"빨리 누르는 진짜 팬은요?"** → 속도가 아니라 '5번 연속 똑같은가'를 봅니다. 0초에 연타하는 사람도 1.2%만 해당됐습니다.
- **"지연을 섞으면요?"** → 실험했습니다. 50ms만 섞어도 시간만으로는 어렵습니다(6절). 그래서 계정·기기 신호를 함께 봅니다. 이번 시연은 일반 매크로가 범위입니다.
- **"지방 사용자가 불리하지 않나요?"** → 판정에 지역·IP를 쓰지 않습니다. 시연에서 대전·판교 사람 차단율은 모두 0%였습니다.
- **"AI가 틀리면요?"** → 알려진 사람이 한 명이라도 걸리면 스스로 배포를 멈춥니다(실험 중 실제로 두 번 멈췄음). 운영자는 버튼 하나로 되돌립니다.

## 10. 재현 방법 (판교에서)

```bash
bash sim/up.sh                                    # 실험판 + 계정 시드 (사람 60, 봇 30)
python3 bots/rounds.py --base http://172.17.0.1:18198,http://172.17.0.1:18199 \
    --every 1 --rounds 12 --copies 3 --humans 40 --out sim/rounds.jsonl --yes   # 수집
bash sim/dump_log.sh                              # detection-log -> sim/out (서울 보관 형식)
python3 seoul/round_report.py sim/rounds.jsonl --archive sim/out              # v0 결과표
python3.11 seoul/train_rules.py sim/rounds.jsonl --archive sim/out --upto 38  # 서울: 학습·교차 검증
python3 sim/stress.py                             # 6절 표
# 자동 반영: SIM_FILTER_MODE=enforce 로 PoP 재생성 후 seoul/auto_rules.py 실행, rounds.py --bot-from 40 --bot-count 9
bash sim/down.sh                                  # 흔적 없이 지우기
```

좌석이 다 차면 `bash sim/reset_seats.sh`로 실험판 좌석만 되돌린다(로그는 남음).
