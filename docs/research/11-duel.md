# 같은 순간 클릭 대결: 기존 방식 vs DOON (실서비스)

측정일: 2026-10-16 18:05~18:08 KST · 스크립트: `scripts/duel.py`, `scripts/duel_report.py`

질문: **판교와 대전에서 같은 순간에 누르면, 기존 방식과 DOON에서 각각 누가 이기나.**

## 한 줄 결론

> 같은 순간에 눌렀을 때 **기존 방식(서버 도착순)에서는 대전이 99번 중 한 번도 못 이겼다.**
> **DOON에서는 99번 중 54번 이겼다.**

## 방법

- 판교 서버와 대전 서버(둘 다 chrony로 시계를 맞춘 PoP 호스트)가 같은 예약 시각에 같은 좌석으로 요청을 한 건씩 보낸다. 좌석 200개, 1초 간격.
- 좌석을 번갈아 두 방식으로 나눴다(시간대 영향이 양쪽에 고르게 가도록).
  - **기존 방식 (DUEL-B)**: 대전 요청도 판교 PoP로 보낸다. 두 요청이 판교 PoP 한 시계로 찍히므로, **도착 순서로 승자를 센다.** 국내 대기열이 서버에 먼저 닿은 순서대로 순번을 주는 것과 같은 조건이다.
  - **DOON 방식 (DUEL-D)**: 대전 요청은 대전 PoP로 보낸다. **중앙이 실제로 정한 승자**(보정 시각 + 시계 보장 범위 안 추첨)를 그대로 센다.
- 연결은 미리 열어 두었다(이미 예매 페이지에 들어와 있는 사람과 같은 조건, TCP 연결 시간 제외).
- 실서비스(판교·대전 PoP, 중앙)에 보냈다. 실험 좌석은 실제 좌석 지도와 겹치지 않게 `DUEL-*` 이름을 썼고, 끝난 뒤 `reset_live.sh`로 지웠다(0/608 확인).

## 결과

| | 기존 방식 (둘 다 판교, 도착순) | DOON (각자 가까운 PoP) |
|---|---|---|
| 비교된 좌석 | 99 | 99 |
| **대전 승** | **0 (0%)** | **54 (55%)** |
| 대전 도착이 판교보다 늦은 정도 | 중앙값 **2.18ms** (최소 1.55, 90% 지점 45.8) | 보정 후 중앙값 −0.37ms (−0.74 ~ +0.26) |
| 승자를 정한 방식 | 도착 순서 | 99좌석 모두 시계 보장 범위 안 → 검증 가능한 추첨 |
| 시계 보장 오차 (그 시각) | — | 판교 1.37ms, 대전 2.45ms |

읽는 법:

1. **기존 방식에서 대전은 늘 졌다.** 대전 요청은 판교까지 중앙값 2.18ms 늦게 도착했다. 예매 사이트 5곳에 직접 잰 지역 차이(평균 2.07ms, [06](06-regional-gap.md))와 같은 크기다.
2. **DOON에서는 그 2ms가 판정에서 빠졌다.** 두 요청의 보정 시각 차이가 1ms 안으로 줄었다.
3. **1ms 안의 차이는 시계로 가를 수 없는 범위라 추첨으로 정했다.** 이 범위에서 보정 시각만으로 가르면 대전이 91/99를 이겼다. 반대 방향 편향이다. 추첨이 이것도 막아 54:45가 됐다(공정한 동전을 99번 던지면 앞면은 95% 확률로 40~59번 사이에 나온다).

## 한계

- 대전 → 판교 경로는 대전 망의 중계 프록시를 거친다. 그래서 일부 좌석은 대전이 수십 ms 늦었다(99개 중 32개가 5ms 초과). 중앙값(2.18ms)은 프록시가 없는 예매 사이트 측정과 같은 크기라, 결론(기존 방식에서 대전 0승)은 프록시 꼬리가 없어도 같다. 가장 작은 차이도 1.55ms였다.
- 요청을 보낸 것은 휴대폰이 아니라 두 지역의 서버다. 사용자 → 가장 가까운 PoP 구간은 실험에 들어 있지 않다.
- 방식마다 100좌석 중 1좌석은 한쪽 요청이 빠져 비교에서 뺐다.
- DOON에서 대전 54승은 추첨 결과다. "대전이 더 유리하다"가 아니라 "어느 쪽에도 기울지 않았다"로 읽는다.

## 재현

```bash
# 판교와 대전에서 같은 --start 로 (대전은 daejeon_relay.sh 중계가 살아 있어야 함)
python3 scripts/duel.py --side pangyo  --start 18:05:00 --n 100 --out duel.jsonl     # 판교
python3 scripts/duel.py --side daejeon --start 18:05:00 --n 100 --out duel_dj.jsonl  # 대전
# 판교에서 집계
docker compose -f docker-compose.pangyo.yml exec -T kafka /opt/kafka/bin/kafka-console-consumer.sh \
    --bootstrap-server localhost:9092 --topic seat-status --from-beginning --timeout-ms 20000 | grep DUEL > status.txt
python3 scripts/duel_report.py duel.jsonl status.txt
bash scripts/reset_live.sh   # 실험 좌석 지우기
```
