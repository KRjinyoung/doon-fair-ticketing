# 매크로 3단계 방어 + 1·2차 규칙 정교화 — 구현 설계

작성일: 2026-10-16 · 브랜치 `feat/macro-3layer` · 원안: 팀 설계(에스티씨랩 봇매니저·기술 블로그 분석)

## 한 줄

> 1차(PoP)는 요청 한 건을 규칙으로, 2차(중앙)는 전국 PoP를 모은 현재 상태를 규칙으로, 3차(서울 AI)는 여러 회차에 걸친 행동을 학습 모델로 본다.
> 3차는 판정에 끼어들지 않고 명단을 2차(와 1차)에 보내며, 1·2차 규칙의 값을 다시 계산해 정교화한다.

## 1. 수집

| 시점 | 값 | 어디에 |
|---|---|---|
| 로그인 | 계정 나이 `age`, 기기 지문 `dfp`, 로그인 IP `lip`, 세션 `sid` | JWT 클레임(봉인) + `sessions` 테이블 |
| 좌석 요청마다 | IP, User-Agent, 헤더, PoP 도착 시각(µs) + JWT 신원 | detection-log, seat-requests |

## 2. 규칙 묶음 (Kafka `bot-rules`, 한 버전 = 한 메시지)

```json
{"version": "v3-ai-r12", "approved_by": "auto-check", "approved_at": "...",
 "params": {
   "l1": {"rate": {"ip": [10, 30], "account": [10, 20], "device": [10, 30]},
          "ua_tokens": ["python", "curl", "..."], "block_ttl_sec": 3600},
   "l2": {"rate": {"account": [10, 30], "device": [10, 40]},
          "device_accounts": {"max": 3, "young_days": 7},
          "hold": {"max_unpaid": 2}}},
 "blacklist": {"accounts": [], "devices": []},
 "rules": [{"id": "r1", "layer": 1, "mode": "shadow", "why": "...", "all": [{"f": "...", "op": "...", "v": "..."}]}]}
```

- `rate: [창(초), 한도]`. 빠진 값은 기본값을 쓴다(지금까지의 v0 값).
- `mode`: `enforce`(막음) / `shadow`(막지 않고 "막았을 것"만 기록). 정교화의 그림자 배포에 쓴다.
- 1차는 `layer: 1` 규칙과 명단을, 2차는 `layer: 2` 규칙과 명단을 쓴다.

## 3. 단계별 판정

| 단계 | 보는 범위 | 항목 | 걸리면 |
|---|---|---|---|
| 1차 PoP | 요청 한 건 + 이 PoP의 최근 요청 | ① 위조 토큰 ② 차단 목록(IP·계정·기기, TTL) ③ IP·계정·기기별 요청 수 ④ User-Agent ⑤ 3차 명단 ⑥ 1차 규칙 | 403/429, detection-log 에 사유 |
| 2차 중앙 | 전국 PoP를 모은 현재 상태 + 중앙 DB | ① 신원 대조(세션이 이 계정·기기의 것인가) ② 기기당 계정 수(계정 나이와 함께: 오래된 계정끼리 공유 = PC방, 제외) ③ 미결제 선점 횟수 ④ 전국 합산 계정·기기별 요청 수 ⑤ 3차 명단 ⑥ 2차 규칙 | **판정 후보에서 제외**(순서·추첨은 그대로), detection-log 에 `second_layer_block` |
| 3차 서울 | 전국 · 여러 회차 | 계정 나이, 기기당 계정 수, 동시에 노린 좌석 수, 요청 간격 분포 모양, 회차 간 도착 흩어짐 | 계정별 봇 확률 + 근거 → 명단·규칙 값 발행 |

2차는 판정 함수(정렬·추첨·Redis Lua) **앞에서** 거른다. 메모리·Redis 두 경로가 같은 검사를 받는다.

## 4. 좌석 선점 (결제 단계)

```
창 마감 → 승자 = held (결제 기한 HOLD_SEC) → 결제(POST /payment) → confirmed
                                      └→ 기한 초과 → available 로 반환, 계정의 미결제 횟수 +1
```
2차 ③은 미결제 횟수가 한도를 넘은 계정을 다음 요청부터 후보에서 뺀다.

## 5. 1·2차 규칙 정교화 (3차가 돌림)

1. **기록**: 1·2차는 요청마다 걸린 규칙(그림자 포함)과 규칙 버전을 남긴다.
2. **채점**: 3차의 계정별 봇 확률을 기준으로 규칙마다 잡은 봇 / 놓친 봇 / 걸린 믿을 만한 사람을 센다.
3. **제안**: (a) 한도 다시 계산: 놓친 봇은 최대로, 믿을 만한 사람은 0명 (b) 새 규칙: 놓친 봇에만 공통인 패턴을 짧은 규칙으로 — 요청 한 건으로 판단되면 1차, 집계가 필요하면 2차 (c) 안 걸리거나 사람만 거는 규칙은 끔.
4. **재실행**: 저장된 로그에 같은 판정 함수로 다시 돌려 지금 규칙과 비교.
5. **그림자 배포** → 6. **승격**(enforce), 버전 기록. 비상 시 이전 버전으로 복귀.

고정 기준점: 믿을 만한 사람 목록이 한 명이라도 걸리는 제안은 버린다(1·2차 → 3차 → 1·2차 고리가 폭주하지 않게).
