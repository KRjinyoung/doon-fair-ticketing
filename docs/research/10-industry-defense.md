# 업계의 매크로 방어와 DOON의 차별점 (2026-10-15 조사)

[09-ai-macro-results.md](09-ai-macro-results.md)의 실험 결과를 업계 방어와 나란히 놓고, DOON이 다른 점과 하지 않는 점을 정리한다.
업체 자료(에스티씨랩, Queue-it 등)는 홍보 성격이 있어 숫자는 참고용이다.

## 한 줄 요약

> 업계는 **"누가 봇인가"를 블랙박스로 판단**하고, 그 대가로 **지역·국가 차별 논란과 팬의 소명 부담**이 생긴다.
> DOON은 **"먼저 누른 사람이 이긴다"는 순서를 지키면서**, 지역을 보지 않는 **설명 가능한 한 줄 규칙**으로 매크로를 걸러낸다.

## 1. 업계는 어떻게 막나 — 다섯 겹

| 단계 | 방법 | 사례 |
|---|---|---|
| **① 들어오기 전** | 가상 대기열 | 넷퍼넬(에스티씨랩), Queue-it, 티켓마스터 Smart Queue |
| | 오픈 전 도착자 무작위 순번 | Queue-it 사전 대기열. "빠른 인터넷·봇의 이점을 없애려고" 랜덤 |
| | 사전 등록 후 선별된 팬에게만 코드 | 티켓마스터 Verified Fan (참석 이력 등으로 ML 선별) |
| | 팬클럽 멤버십 사전 인증 | 지드래곤(공식 커뮤니티 서베이 + 예매처 인증), 쿠팡플레이(팬클럽과 같은 실명 계정) |
| | 추첨제 | 일본에서 일반적. 국내는 일부 |
| **② 요청 단계 (실시간 봇 탐지)** | IP 평판: 해외·데이터센터 IP 차단 | Queue-it 요청의 40%를 데이터센터 IP로 차단. 예스24 매크로 트래픽 60% 이상이 해외 IP |
| | 헤더·자동화 도구 탐지 (셀레니움 등) | 에스티씨랩 봇매니저 '정적 분석' |
| | TLS 지문(JA3/JA4) | Cloudflare Bot Management (엔터프라이즈) |
| | 행동 분석: 요청 속도, 클릭 패턴, 마우스·터치·가속도 → ML 점수 | 에스티씨랩 '동적 분석', Queue-it |
| | 보안문자(캡차) | Queue-it 차단의 24%가 캡차 실패 |
| | 반복 접속·구매 행태 감지 | 코레일 2026 설 예매 기간 비정상 접근 42,695건 선제 차단, 적발 판매자 회원 탈퇴 |
| | 이상거래탐지시스템 | NHN링크(티켓링크), 놀유니버스(NOL 티켓) 자체 시스템 |
| **③ 구매 단계** | 1인 매수 제한 | 대부분 예매처. 다중 계정으로 우회됨 (판례: 계정 3개로 26장) |
| **④ 판매 후·입장** | 플랫폼이 의심 예매를 자체 취소 | 소명은 팬이 부담 |
| | 입장 본인 확인 | 신분증 대조(데이식스), 하이브 얼굴패스(토스·NOL 티켓) |
| | 거래 데이터 + 입장 본인 확인 | 마스킷 '암표재판관': 11,543장 중 암표 100건 입장 단계에서 무효화 |
| | 재판매 가격 상한 | 티켓베이 1매 100만 원 이하 (2026-01) |
| **⑤ 법·수사** | 공연법 개정 | 2024-03 매크로 암표 처벌 → 2026-08 시행: 매크로 여부와 무관하게 부정 구매·판매 금지, **판매자에게 기술적·관리적 조치 의무**, 최대 50배 과징금 |
| | 경찰·예매처 공조 | 2026-05 국가수사본부·놀유니버스·NHN링크 설명회: 수사관에게 매크로 판별 '기술적 지표' 교육 |

## 2. 업계 방어의 약점 (보도·자료에서 나온 것)

| 약점 | 근거 |
|---|---|
| **매크로 사용을 입증하기 어렵다** | 뉴데일리 2026-07. 경찰이 수사관에게 '기술적 지표'를 따로 교육할 정도 |
| **판단이 블랙박스다 → 팬이 소명** | 플랫폼이 의심 예매를 자체 취소하고 소명은 팬 몫 (마리끌레르 2026-03) |
| **지역·국가로 거르면 차별 논란** | 해외·데이터센터 IP 차단이 주요 수단. 국가별 티켓팅 제한 요구는 "차별 요소와 실효성 문제" (마리끌레르) |
| **줄 세우기는 여전히 '서버 도착순'** | 대기열은 서버에 먼저 닿은 순서. 서버에서 먼 지역이 불리하다 (06 실측: 전남 +1.3~3.5ms). 무작위 순번은 이걸 없애는 대신 선착순을 포기 |
| **매수 제한은 다계정에 뚫린다** | 의정부지법 2026-06 판례: 가족·지인 명의 3개 계정으로 13회에 26장 |
| **본인 확인은 무겁다** | 얼굴패스는 개인정보 우려와 낮은 호응 (마리끌레르). 사전 인증은 팬클럽 없는 공연·열차표에 쓰기 어렵다 |

## 3. DOON의 차별점

| | 업계 | DOON |
|---|---|---|
| **순서와 탐지의 관계** | 탐지는 서버 앞단 별도 장치. 순서는 서버 도착순이거나 추첨(선착순 포기) | **엣지에서 시각을 먼저 찍고, 탐지는 '자격'만 판단.** 봇을 걸러도 남은 사람의 순서는 그대로. 거리 차이(엣지 스탬핑)와 도구 차이(매크로 방지)를 한 판정 구조에서 없앤다 |
| **판단 근거** | 위험 점수(블랙박스) | **"5번 연속 도착 시각이 12ms 안에서 같으면 매크로"** 한 줄. 요청마다 µs 시각·규칙 버전·판정이 로그에 남아 **같은 로그로 같은 판정을 재현**할 수 있다 → 소명, 수사, 법의 '기술적 조치 의무' 증빙에 바로 쓰인다 |
| **지역·IP** | 해외·데이터센터 IP 차단이 핵심 수단 | **지역·IP·PoP를 판단에 쓰지 않는다.** 판교·대전 사람 차단율 모두 0% 실측 |
| **사용자 부담** | 캡차, 사전 인증, 얼굴 등록 | 추가 단계 없음 (업계 수단과 함께 쓸 수 있음) |
| **규칙 갱신** | 업체가 정책·임계치를 조정 | 서울 AI가 회차마다 다시 배우고, **알려진 사람이 한 명이라도 걸리면 스스로 배포를 멈춘 뒤**, 통과하면 0.2초 만에 전국 PoP에 반영 |
| **기반** | 상용 클라우드·CDN | KOREN 전국 PoP에서 찍고, 로그는 KOREN으로 서울 AI Cloud에 모은다 |

발표용 문장:

> 업계의 매크로 방어는 '누가 봇인가'를 블랙박스로 판단합니다. 그래서 입증이 어렵고, 지역으로 거르면 차별 논란이 생기고, 줄은 여전히 서버 도착순입니다.
> DOON은 전국 PoP에서 먼저 시각을 찍어 거리의 차이를 없애고, 지역을 보지 않는 한 줄 규칙으로 도구의 차이를 없앱니다. 모든 판정은 같은 로그로 다시 재현할 수 있습니다.

## 4. DOON이 하지 않는 것 (솔직하게)

업계 수단을 대체하지 않는다. 함께 쓰는 한 층이다.

| 업계 수단 | DOON | 이유 |
|---|---|---|
| IP 평판, TLS 지문, 마우스·터치 생체 신호 | 안 씀 | 지역 공정성(IP), HTTP 환경(TLS), 클라이언트가 보내는 값이라 위조 가능(마우스, 08 결정) |
| 캡차, 사전 인증, 본인 확인 입장 | 안 씀 | 범위 밖. 그대로 함께 쓰면 된다 |
| 1인 매수 제한, 결제 대조 | 안 씀 | 판정 = 확정 구조라 결제 단계가 없음 |
| 대리 예매, 지연 섞는 고급 봇 | 못 잡음 | 09 0절·6절 |
